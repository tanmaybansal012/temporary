# Digital Logic Simulator: Technology Stack and Python Libraries

This document breaks down all the Python libraries and the technology stack used in this Digital Logic Simulator, including what each component is doing and why it was chosen.

### 1. The Core Engine (Standard Library Only)
**Stack:** `Python 3 Standard Library` (`itertools`, `typing`, `sys`, `os`)
*   **What it does:** The entire core logic of the simulator (defining logic gates, topological sorting of circuits, clock synchronization, propagating logic levels, and generating truth tables) is built purely using Python's standard library. 
*   **Why it's used:** By strictly avoiding third-party libraries in the core engine, the simulator is exceptionally fast, lightweight, and completely portable. You don't have to worry about dependency conflicts when running a core simulation. `itertools` is specifically critical here for mathematically generating the Cartesian products ($2^n$ inputs) for the truth tables.

---

### 2. Mathematics and Data Structures
**Stack:** `SymPy`, `Pandas`
*   **`sympy` (Symbolic Python):** 
    *   **What it does:** Used inside `expression.py`. It provides a powerful algebraic engine to manipulate Boolean math. 
    *   **Why it's used:** When you have a massive logic circuit, you often want to extract the equivalent Boolean algebra equation and simplify it to Sum of Products (SOP) or Product of Sums (POS). `sympy` does this heavy mathematical lifting automatically.
*   **`pandas`:** 
    *   **What it does:** Used inside the web interfaces (like `streamlit_app.py`).
    *   **Why it's used:** It takes the raw dictionaries generated by the State Table generator and converts them into beautiful, sortable, and easily readable dataframes for the web interface.

---

### 3. Data Visualization & Rendering
**Stack:** `Matplotlib`, `Plotly`, `SchemDraw`
*   **`matplotlib`:** 
    *   **What it does:** Used in `waveform.py` to generate static `.png` images of the timing diagrams.
    *   **Why it's used:** It is the industry standard for 2D plotting. It has a specific drawing style called "step-post" which perfectly replicates the sudden 0-to-1 voltage jumps needed for digital timing diagrams.
*   **`plotly`:** 
    *   **What it does:** Used in `plotly_waveform.py` to create dynamic, interactive waveforms for the web application.
    *   **Why it's used:** Unlike Matplotlib which just creates a flat image, Plotly generates HTML/JavaScript graphs. This allows the user to hover over signals, zoom into specific time steps, and pan across the waveform directly in their web browser.
*   **`schemdraw`:** 
    *   **What it does:** Used in `render.py`.
    *   **Why it's used:** It physically draws the circuit. It takes the text-based netlist (e.g., "AND gate connected to OR gate") and automatically draws standard electrical engineering schematics so the user can visually see the logic gates.

---

### 4. Web Application Frameworks
**Stack:** `Streamlit`, `Flask`
*   **`streamlit` (`streamlit_app.py`):** 
    *   **What it does:** Serves as the primary modern graphical user interface (GUI) for the simulator.
    *   **Why it's used:** Streamlit allows developers to build beautiful, highly interactive web applications for data and engineering tools purely in Python. It handles the UI layout, file uploading, buttons, and embedding the Plotly graphs without needing to write complex React or CSS frontends.
*   **`Flask` (`app.py`):** 
    *   **What it does:** Provides a traditional HTTP backend web server. 
    *   **Why it's used:** Flask is likely used as an API server (or for serving traditional HTML from the `templates/` folder). It allows other applications to send HTTP requests to run simulations remotely or serves as a lightweight alternative to the Streamlit GUI.

---

### 5. Quality Assurance
**Stack:** `pytest`
*   **What it does:** Used in the `tests/` directory.
*   **Why it's used:** `pytest` is the standard testing framework for Python. It automatically runs hundreds of assertions (e.g., asserting that `1 AND 0` is `0`, and ensuring flip-flops hold state) to guarantee that the simulator math is mathematically perfect before any code is deployed.
